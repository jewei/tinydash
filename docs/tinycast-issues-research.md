## Product lessons

### Clipboard history is a core workflow, with competing defaults

Users ask for more than storage and paste. They want the last copied item selected, multi-select paste, inline editing, deletion of all unpinned entries, drag and drop, image preview, OCR, duplicate filtering, file saving, and search filters. The current tracker has an open request for last-item selection (#878), inline editing (#846), multi-select paste (#845), and deleting non-pinned entries (#780). Older requests cover the original feature and pinning (#151, #49), drag and drop (#544), large-entry limits (#770), image preview (#740), OCR (#695), file saving (#758), and image filters (#233). See [#878](https://github.com/abue-ammar/tinycast/issues/878), [#846](https://github.com/abue-ammar/tinycast/issues/846), [#845](https://github.com/abue-ammar/tinycast/issues/845), [#780](https://github.com/abue-ammar/tinycast/issues/780), [#544](https://github.com/abue-ammar/tinycast/issues/544), [#770](https://github.com/abue-ammar/tinycast/issues/770), [#695](https://github.com/abue-ammar/tinycast/issues/695), and [#233](https://github.com/abue-ammar/tinycast/issues/233).

The request is not one consistent preference. One user wants the newest item selected, while the current product selects a pinned item first. Other users want a setting to stop automatic paste or choose the primary clipboard action. The maintainer explicitly rejected the primary-action setting in [#341](https://github.com/abue-ammar/tinycast/issues/341#issuecomment-5415659998); [#342](https://github.com/abue-ammar/tinycast/issues/342) was reported as a duplicate of that thread. A later #343 thread says the copy-first behavior exists and receives a positive maintainer reply, so it is not evidence of an unresolved rejection ([#343](https://github.com/abue-ammar/tinycast/issues/343#issuecomment-5684049826)). Tinydash should make the selection and paste behavior explicit, and keep pins separate from recency. Duplicate or related reports include #49/#292/#878 for pinned or initial selection, #151/#545/#878 for initial selection, and #233/#403 for image filtering. These are related demand clusters, not counts of independent users.

Large and unusual payloads cause real failures. Reports include preview stalls on paragraph-heavy mixed-language text, stale clipboard contents after long snippet insertion, and paste failures when AeroSpace is running ([#453](https://github.com/abue-ammar/tinycast/issues/453), [#427](https://github.com/abue-ammar/tinycast/issues/427), [#281](https://github.com/abue-ammar/tinycast/issues/281)). The maintainer declined the requested large-entry size limit and preview truncation in [#770](https://github.com/abue-ammar/tinycast/issues/770#issuecomment-5692099941). Design the history around text, images, and file URLs as distinct payload types. Bound preview work and preserve the previous application and pasteboard state.

### Search must handle metadata, ranking, and scope failures

Application discovery reports cover nested folders, custom folders, embedded apps, PWAs, renamed apps, localized names, empty bundle display names, duplicate bundle IDs, and Xcode companion apps. Examples are [#790](https://github.com/abue-ammar/tinycast/issues/790), [#407](https://github.com/abue-ammar/tinycast/issues/407), [#219](https://github.com/abue-ammar/tinycast/issues/219), [#371](https://github.com/abue-ammar/tinycast/issues/371), [#141](https://github.com/abue-ammar/tinycast/issues/141), [#103](https://github.com/abue-ammar/tinycast/issues/103), and [#499](https://github.com/abue-ammar/tinycast/issues/499). Several early reports were resolved by adding configurable application scopes, but later reports show that scope and metadata still leave gaps ([#94](https://github.com/abue-ammar/tinycast/issues/94), [#111](https://github.com/abue-ammar/tinycast/issues/111), [#256](https://github.com/abue-ammar/tinycast/issues/256)).

Ranking also changes perceived correctness. Users ask to search by previous names, hide unwanted results, see frequent or recent searches, search extension names, and avoid a short query such as `out` selecting Log Out instead of Outlook ([#821](https://github.com/abue-ammar/tinycast/issues/821), [#772](https://github.com/abue-ammar/tinycast/issues/772), [#567](https://github.com/abue-ammar/tinycast/issues/567), [#295](https://github.com/abue-ammar/tinycast/issues/295)). Tinydash should keep stable metadata aliases and allow a user to inspect why a result matched.

### Keyboard state and navigation need one consistent model

Many reports concern what Return, Escape, Backspace, Command-K, and arrow keys do at boundaries. The tracker includes stuck extension state after a hotkey-launched command ([#787](https://github.com/abue-ammar/tinycast/issues/787)), an actions menu that cannot reach detail actions ([#837](https://github.com/abue-ammar/tinycast/issues/837)), a missing wrap from the first actions-menu row ([#838](https://github.com/abue-ammar/tinycast/issues/838)), an empty-field Escape path that can open clipboard history ([#523](https://github.com/abue-ammar/tinycast/issues/523)), and Backspace failing to return from AI ([#616](https://github.com/abue-ammar/tinycast/issues/616)). The maintainer declined Vim-style bindings and several Raycast-like action-menu search requests because of keyboard-layout and scope concerns ([#786](https://github.com/abue-ammar/tinycast/issues/786#issuecomment-5710126111), [#656](https://github.com/abue-ammar/tinycast/issues/656#issuecomment-5662710568), [#416](https://github.com/abue-ammar/tinycast/issues/416#issuecomment-5666432096)). A later approved issue asks for action search again ([#777](https://github.com/abue-ammar/tinycast/issues/777)).

The lesson for Tinydash is to define a small state transition table before adding shortcuts. Test empty, first, last, nested, hotkey-launched, and restored states. Do not use closed status as proof of a fix. The newest Settings report says that dismissing Settings quits the whole app ([#879](https://github.com/abue-ammar/tinycast/issues/879)); it is open and has no maintainer resolution.

### Extension compatibility is a large maintenance cost

Tinycast's extension layer reports missing or incompatible Node and Web APIs, bundler export errors, file and URL behavior differences, authentication failures, and rendering gaps. Examples include Node shim exports and `__toESM` ([#852](https://github.com/abue-ammar/tinycast/issues/852)), `Blob` and `FormData` ([#618](https://github.com/abue-ammar/tinycast/issues/618)), `fs.opendirSync` ([#714](https://github.com/abue-ammar/tinycast/issues/714)), `node-fetch` ([#405](https://github.com/abue-ammar/tinycast/issues/405)), response streams ([#429](https://github.com/abue-ammar/tinycast/issues/429)), `safer-buffer` ([#712](https://github.com/abue-ammar/tinycast/issues/712)), and crypto APIs required by Bitwarden ([#643](https://github.com/abue-ammar/tinycast/issues/643)). UI compatibility gaps include action-panel semantics, metadata placement, image sizing, and Safari bookmark rendering ([#793](https://github.com/abue-ammar/tinycast/issues/793), [#783](https://github.com/abue-ammar/tinycast/issues/783), [#803](https://github.com/abue-ammar/tinycast/issues/803), [#839](https://github.com/abue-ammar/tinycast/issues/839), [#818](https://github.com/abue-ammar/tinycast/issues/818)).

Performance is part of compatibility. One report measured roughly a one-second delay when navigating 400 rows with large action panels because SwiftUI compared nested render trees ([#867](https://github.com/abue-ammar/tinycast/issues/867)). A Tinydash extension system should publish its supported runtime surface, fail with a specific missing-capability message, and test large lists. Do not promise broad compatibility from a thin adapter.

### Calculator and time parsing need conservative failure behavior

Users request aliases, natural word order, named dates, locale forms, and less typing. Current examples include Singapore `SGT`, Argentina aliases, place-first and `timezone` phrases, named-date conversions, implicit currency conversion, `NTD`, `RMB`, modulo, scientific notation, implicit multiplication, and base conversion ([#874](https://github.com/abue-ammar/tinycast/issues/874), [#796](https://github.com/abue-ammar/tinycast/issues/796), [#873](https://github.com/abue-ammar/tinycast/issues/873), [#795](https://github.com/abue-ammar/tinycast/issues/795), [#792](https://github.com/abue-ammar/tinycast/issues/792), [#539](https://github.com/abue-ammar/tinycast/issues/539), [#293](https://github.com/abue-ammar/tinycast/issues/293), [#754](https://github.com/abue-ammar/tinycast/issues/754), [#86](https://github.com/abue-ammar/tinycast/issues/86), and [#84](https://github.com/abue-ammar/tinycast/issues/84)).

The highest risk is a plausible wrong answer. Issues report a source name being damaged by filler-word removal and a dated conversion silently using the device zone ([#872](https://github.com/abue-ammar/tinycast/issues/872), [#795](https://github.com/abue-ammar/tinycast/issues/795)). Another issue reports a two-day conversion labelled as tomorrow ([#729](https://github.com/abue-ammar/tinycast/issues/729)). Tinydash should preserve the full place phrase, keep the date attached to the source moment, and return no card when the parser cannot prove the source. Locale and unit aliases need table-driven tests. Tinycast's maintainer explicitly rejected comma decimal and locale support in [#60](https://github.com/abue-ammar/tinycast/issues/60#issuecomment-5104733738), so these requests are demand signals even where the upstream decision is no.

### Notes need editor behavior, storage choices, and window rules

Note requests include multiple floating windows, find, undo, inline Markdown, task checkboxes, configurable storage folders, title editing, first-line titles, font size, and IME-safe placeholder behavior ([#863](https://github.com/abue-ammar/tinycast/issues/863), [#736](https://github.com/abue-ammar/tinycast/issues/736), [#735](https://github.com/abue-ammar/tinycast/issues/735), [#471](https://github.com/abue-ammar/tinycast/issues/471), [#798](https://github.com/abue-ammar/tinycast/issues/798), [#773](https://github.com/abue-ammar/tinycast/issues/773), [#271](https://github.com/abue-ammar/tinycast/issues/271), [#413](https://github.com/abue-ammar/tinycast/issues/413), [#476](https://github.com/abue-ammar/tinycast/issues/476), and [#851](https://github.com/abue-ammar/tinycast/issues/851)). Keep document identity, title, editor state, search, and window lifetime separate. Test IME composition and reopening a note window.

### AI providers and credentials are a boundary, not one feature

Requests span installed CLI accounts, Ollama, Grok, Cursor, DeepSeek, model selection, reasoning effort, dynamic API keys, custom endpoints, MCP OAuth, and custom AI actions ([#794](https://github.com/abue-ammar/tinycast/issues/794), [#807](https://github.com/abue-ammar/tinycast/issues/807), [#833](https://github.com/abue-ammar/tinycast/issues/833), [#564](https://github.com/abue-ammar/tinycast/issues/564), [#682](https://github.com/abue-ammar/tinycast/issues/682), [#456](https://github.com/abue-ammar/tinycast/issues/456), [#856](https://github.com/abue-ammar/tinycast/issues/856), [#857](https://github.com/abue-ammar/tinycast/issues/857), and [#804](https://github.com/abue-ammar/tinycast/issues/804)). The custom Codex endpoint bug is a useful state-model lesson: missing an account object does not mean signed out when the protocol says OpenAI authentication is not required ([#857](https://github.com/abue-ammar/tinycast/issues/857)).

At the time of those threads, the maintainer rejected AI transforms and broad tool calling while stating a preference for small, BYOK-style chat. The decisions and the reason, including Accessibility limitations for selected text, are recorded in [#516](https://github.com/abue-ammar/tinycast/issues/516#issuecomment-5598368131) and [#314](https://github.com/abue-ammar/tinycast/pull/314#issuecomment-5400225359). Later implementation may change the product, so these comments are historical decisions rather than proof that the capability is absent now. Tinydash should keep provider discovery, authentication state, model choice, and data access separate. Do not infer demand for agent tool access from a single proposal. The ledger records each related request and its decision.

### Calendar integration fails at permissions and external data seams

Calendar reports include missing permissions, meetings that fail to open, account-specific Google Meet links, browser choice, today's-only filtering, and hiding the menu item when there are no events ([#538](https://github.com/abue-ammar/tinycast/issues/538), [#648](https://github.com/abue-ammar/tinycast/issues/648), [#876](https://github.com/abue-ammar/tinycast/issues/876), [#865](https://github.com/abue-ammar/tinycast/issues/865), [#361](https://github.com/abue-ammar/tinycast/issues/361), and [#859](https://github.com/abue-ammar/tinycast/issues/859)). The newer #876 report gives a precise EventKit seam: `absoluteString` contains the `mailto:` address while `path` is empty. This is a warning to test real framework objects, not only hand-built URL fixtures.

The hide-when-empty request appears twice, as #817 and the newer open #859. The maintainer rejected #817 because of perceived background work and memory cost, even after a commenter supplied a no-polling design. Treat this as one demand cluster with a maintainer rejection, not two independent feature counts ([#817](https://github.com/abue-ammar/tinycast/issues/817#issuecomment-5705060828), [#859](https://github.com/abue-ammar/tinycast/issues/859)).

### macOS behavior creates platform-specific edge cases

Reports cover Caps Lock and Hyper Key state, input-source changes, multi-monitor placement, window cycling, system modal visibility, Liquid Glass, external audio devices, permissions, notarization, Homebrew launch failures, and Intel versus Apple Silicon packages. Examples include [#759](https://github.com/abue-ammar/tinycast/issues/759), [#653](https://github.com/abue-ammar/tinycast/issues/653), [#665](https://github.com/abue-ammar/tinycast/issues/665), [#723](https://github.com/abue-ammar/tinycast/issues/723), [#724](https://github.com/abue-ammar/tinycast/issues/724), [#663](https://github.com/abue-ammar/tinycast/issues/663), [#785](https://github.com/abue-ammar/tinycast/issues/785), [#844](https://github.com/abue-ammar/tinycast/issues/844), and [#849](https://github.com/abue-ammar/tinycast/issues/849). Window-management demand was strong: #39 received several independent confirmations and led to a shipped feature, while #71 was explicitly marked duplicate ([#39](https://github.com/abue-ammar/tinycast/issues/39), [#71](https://github.com/abue-ammar/tinycast/issues/71)).

Tinydash should test external devices, multiple displays, permission denied states, app activation from another Space, and both Intel and Apple Silicon where applicable. A platform issue closed after a patch or release is evidence of a response, not a guarantee that later macOS versions keep the behavior.

### Settings, backups, and user control are recurring requests

Users ask for hidden UI items, themes, font and palette sizing, configurable data folders, export formats, self-hosted sync, clipboard opt-out, update checks, and custom commands ([#791](https://github.com/abue-ammar/tinycast/issues/791), [#640](https://github.com/abue-ammar/tinycast/issues/640), [#781](https://github.com/abue-ammar/tinycast/issues/781), [#773](https://github.com/abue-ammar/tinycast/issues/773), [#774](https://github.com/abue-ammar/tinycast/issues/774), [#477](https://github.com/abue-ammar/tinycast/issues/477), [#444](https://github.com/abue-ammar/tinycast/issues/444), [#239](https://github.com/abue-ammar/tinycast/issues/239), and [#478](https://github.com/abue-ammar/tinycast/issues/478)). The maintainer often prefers a small fixed behavior over a setting, as shown by the explicit rejections of hiding UI items and per-entry clipboard actions ([#791](https://github.com/abue-ammar/tinycast/issues/791), [#341](https://github.com/abue-ammar/tinycast/issues/341)). Tinydash should add settings only when they resolve a repeated workflow conflict, and should provide a recoverable export before adding sync.

## Maintainer decisions and status limits

The `approved` label means the maintainer allows a contributor to prepare a pull request. It does not mean the feature shipped. The standard bot comment says that only the label is a green light, as visible in [#878](https://github.com/abue-ammar/tinycast/issues/878#issuecomment-5726492329). The repository contains 43 issues labelled `approved` at fetch time.

There are 77 issues labelled `wontfix`. Common reasons are performance or memory cost, a deliberate small scope, keyboard-layout complexity, or a preference for a fork. Examples are screenshot indexing ([#451](https://github.com/abue-ammar/tinycast/issues/451#issuecomment-5598945563)), calendar menu-bar hiding ([#817](https://github.com/abue-ammar/tinycast/issues/817#issuecomment-5705060828)), comma and locale calculator parsing ([#60](https://github.com/abue-ammar/tinycast/issues/60#issuecomment-5104733738)), Vim key bindings ([#786](https://github.com/abue-ammar/tinycast/issues/786#issuecomment-5710126111)), and a broad AI transform proposal ([#314](https://github.com/abue-ammar/tinycast/pull/314#issuecomment-5400225359)).

Some closed threads contain direct resolution evidence. Examples include an app-search scope fix in [#94](https://github.com/abue-ammar/tinycast/issues/94#issuecomment-5120327832), macOS 15 support and a released cask in [#150](https://github.com/abue-ammar/tinycast/issues/150#issuecomment-5185341140), and window-management implementation work in [#39](https://github.com/abue-ammar/tinycast/issues/39#issuecomment-5156027034). Many other closed issues only have the automatic bot comment or a short acknowledgement. The ledger therefore labels state only. It does not translate `closed` into `fixed`.
