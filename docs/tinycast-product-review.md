# Tinycast findings for TinyDash

Prioritize reliable daily use. Complete the existing [public release plan](release-plan.md). Then improve clipboard selection, preserve pins during cleanup, and give users more control over app search names. Treat larger tools as later product options.

These are product recommendations. They do not change the agreed first-release scope.

The user approved the concrete changes on 19 September 2026. See the [implementation record](tinycast-implementation.md) for the delivered changes, checks, and remaining release requirements. The comparisons below describe the source state at the time of this review.

This is a review of public text. Attached images and videos were not all inspected. PR code changes were inspected where needed to explain a finding. The API has no body text for 31 PRs; their titles and available discussions remain in the record. Deleted content, private reports, and external chat are outside this review. The TinyDash comparison uses source commit `bccaa245284cc22a7bc0c96d3083dace3a1950ca` and the current working-tree documents. It does not establish runtime results on every operating system.

Closed status alone does not show that a problem was fixed. For example, the author of [issue 545](https://github.com/abue-ammar/tinycast/issues/545) asked to select the latest clipboard entry while keeping pins above it. The maintainer first declined the request, then said it could be considered during polish. The issue is closed, but the thread does not prove a fix. The same need appears again in [issue 878](https://github.com/abue-ammar/tinycast/issues/878), which is open.

Issue counts show reports in one project's public tracker. They do not show market size. Bot comments, repeat comments, and linked PRs are not separate users. A merged PR shows implementation work. Priority also depends on severity, fit with TinyDash, and the cost of support across three operating systems.

The direct clipboard example is simple. Suppose entry 3 is new and unpinned, entry 2 is older and pinned, and entry 1 is oldest and unpinned. The provider returns `3, 2, 1`. Empty-query pin handling changes this to `2, 3, 1`. The UI selects entry 2. This confirms that the request concerns TinyDash's current behavior, not only the competitor.

Several requested behaviors already exist in TinyDash. Preserve them during later work. These include copy-first clipboard use, clipboard opt-out, category visibility, query retention, window dragging, exact and prefix search bonuses, pins, local date tools, and cached currency. See the [current feature description](../README.md). The source comparison found partial support in some areas. Unicode normalization does not supply translated app metadata. A configured file root does not make folders into searchable results. Transactional migrations do not supply a restorable backup.

The PRs contain useful design warnings for any of these projects. Treat an import as untrusted input, and distinguish wrong credentials, excessive size, and unsupported format. [PR 112](https://github.com/abue-ammar/tinycast/pull/112#issuecomment-5140031851) records a decompression crash. [PR 306](https://github.com/abue-ammar/tinycast/pull/306) separates a large export from a wrong passphrase. An import should preview changes and preserve the current data until validation succeeds.

Fetching a favicon can disclose a private hostname. The unmerged proposal in [PR 824](https://github.com/abue-ammar/tinycast/pull/824) would send quicklink hostnames to an external service. Use local or bundled icons by default. An OAuth review also found callback-state and command-launch concerns in [PR 325](https://github.com/abue-ammar/tinycast/pull/325#pullrequestreview-5009414709). These are design risks to address if TinyDash adds those capabilities.

Keep rendering and background work bounded. The review of a large AI change identified unbounded process output and repeated full-message Markdown parsing in [PR 319](https://github.com/abue-ammar/tinycast/pull/319#pullrequestreview-5002954537). A small list of visible results can still contain expensive previews or action trees. TinyDash already limits result counts and clipboard entry size. New providers must retain those limits or define replacement budgets.

Use this work sequence:

1. Complete the existing combined release requirements. Add the observed focus, keyboard, installation, and large-data cases to verification.
2. After release, deliver the two clipboard changes together. Check selection, both clear actions, All pins, history limits, and restart behavior.
3. Improve search control with aliases, hidden results, and direct category access. Test exact matches, deleted aliases, conflicting shortcuts, and non-US keyboards.
4. Validate custom search templates and snippets with the first users. Select one for the next feature cycle.

For validation, ask users to retrieve a recent clipboard item while older pins exist, clear temporary history, find an app by a familiar name, and open their frequent category. Record task completion, key presses, wrong selections, and requests for help. Repeat the same tasks after each change. Use sample content and the existing [release verification record](release-verification.md). Query logs and copied personal text are unnecessary for these checks.
