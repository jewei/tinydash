## Findings for TinyDash

A merged PR shows that the maintainer accepted and implemented a change. It does not prove demand. A closed PR also does not prove rejection. Tinycast has an automation gate that closes PRs without an approved linked issue. PRs [#797](https://github.com/abue-ammar/tinycast/pull/797) and [#841](https://github.com/abue-ammar/tinycast/pull/841) state this rule directly.

### User reports and repeated demand

- Keyboard and focus behavior is a common source of user friction. Users reported that quick-press Escape did not close the launcher in some environments, including Zed, in [#123](https://github.com/abue-ammar/tinycast/issues/123#issuecomment-5236877394). Users also requested standard Emacs navigation in [#101](https://github.com/abue-ammar/tinycast/issues/101#issuecomment-5157005119) and category search for commands in [#223](https://github.com/abue-ammar/tinycast/issues/223#issuecomment-5238191337).
- Search must handle the text users see. The discussion for [#119](https://github.com/abue-ammar/tinycast/issues/119#issuecomment-5140947505) reports that localized Chinese app names were visible but not reachable from ASCII input. A follow-up user report confirms that system-provided alternate names also matter in [#141](https://github.com/abue-ammar/tinycast/issues/141#issuecomment-5174237771). IME composition produced a separate placeholder bug in [#241](https://github.com/abue-ammar/tinycast/issues/241#issuecomment-5300309246).
- Users wanted the palette to move without losing query state in [#208](https://github.com/abue-ammar/tinycast/pull/208#issuecomment-5230127559). This is a small request with a clear state-preservation rule.
- DMG users asked for in-app update checks because Homebrew does not update those installs in [#137](https://github.com/abue-ammar/tinycast/pull/137#issuecomment-5247427895). The feature was first proposed with Sparkle, then the project later shipped its own updater in [#303](https://github.com/abue-ammar/tinycast/pull/303).

These are direct user reports. Feature titles alone are weaker evidence.

### State, focus, and input edge cases

- [#868](https://github.com/abue-ammar/tinycast/pull/868) reports about one second of arrow-key latency for large extension lists. The cause was deep Equatable comparison through nested action trees. This is a useful warning for list diffing in a launcher.
- [#109](https://github.com/abue-ammar/tinycast/pull/109#issuecomment-5135937580) found a compact-mode regression where the first result overlapped the search field after typing. The list mounted after the initial scroll intent, so the intent needed a safe reassertion.
- [#142](https://github.com/abue-ammar/tinycast/issues/142#issuecomment-5230235583) shows that a delayed scroll correction can create a visible second snap or override newer keyboard or mouse scroll intent. The fix must cancel stale work and bind retries to the current mode.
- [#875](https://github.com/abue-ammar/tinycast/pull/875) found an EventKit seam that ordinary Foundation tests missed. A real `mailto:` URL from EventKit is opaque, while a hand-created Foundation URL exposed a path. Test with platform-produced values at every framework boundary.
- [#749](https://github.com/abue-ammar/tinycast/pull/749) and [#757](https://github.com/abue-ammar/tinycast/pull/757) show that repeated window actions need an origin model. The current display can change during a cycle, so counting from the latest display overshoots.
- A review of [#34](https://github.com/abue-ammar/tinycast/pull/34#discussion_r3658953501) caught that a destructive Quit All command was one Return press away. The resulting fix sampled targets once and moved Return to Cancel. Destructive actions need both a confirmation and a safe default key.
- [#228](https://github.com/abue-ammar/tinycast/pull/228#issuecomment-5248313847) found a CI timing race caused by a test sleep. The test needed an explicit "query started" signal. Time-based sleeps are weak synchronization.

### Performance and resource limits

- [#222](https://github.com/abue-ammar/tinycast/pull/222) measured Spotlight file search at about 0.6 to 0.7 seconds plus debounce, with a 1,000-result bound. The UI keeps old rows visible and shows a searching state. A bounded result set and an explicit stale-query policy are useful for TinyDash.
- [#722](https://github.com/abue-ammar/tinycast/pull/722) fixed fast Settings scrolling that froze the UI, but the Debug process still exceeded the 100 MB memory target after a full scroll. A local improvement is not the same as meeting the product budget.
- [#319](https://github.com/abue-ammar/tinycast/pull/319#pullrequestreview-5002954537) contains high-risk review findings for streaming AI work. They include parsing the full Markdown reply on every token, out-of-order unstructured tasks, an uncapped stdout buffer, and a PID-reuse race in delayed `kill`. Streaming paths need bounded buffers, ordered consumption, incremental or throttled rendering, and process-object termination.
- [#203](https://github.com/abue-ammar/tinycast/pull/203) reports measured launcher work reductions. The useful lesson is to keep before and after numbers for hot paths, not only a general "feels faster" claim.
- [#507](https://github.com/abue-ammar/tinycast/pull/507) and [#503](https://github.com/abue-ammar/tinycast/pull/503) show that clipboard capture and Quick Actions can need memory work even when the feature is small.

### Permissions, privacy, and security

- File Search does not ask on enable, but the first query can trigger macOS Files & Folders prompts for Desktop, Documents, Downloads, and network volumes. The author corrected the earlier assumption in [#222](https://github.com/abue-ammar/tinycast/pull/222#issuecomment-5242424622). Explain the first-use permission before the query.
- Currency conversion raised a direct offline and consent issue. The discussion in [#35](https://github.com/abue-ammar/tinycast/pull/35#issuecomment-5093976326) moved to an explicit opt-in, named provider, six-hour cadence, cache deletion on disable, and no request without consent. Network features need a visible consent boundary and a storage policy.
- [#824](https://github.com/abue-ammar/tinycast/pull/824) proposes sending quicklink hostnames to Raycast's public favicon service. The PR is closed unmerged, so this is a proposed privacy disclosure, not shipped product behavior.
- The OAuth review for [#325](https://github.com/abue-ammar/tinycast/pull/325#pullrequestreview-5009414709) found a missing state check, missing timeout, URL scheme collisions, failing unrelated JavaScript fixtures, and a feature that could let a web page run a command without confirmation. External callbacks need strict state validation, timeouts, narrow routing, and a threat review for every deep-link action.
- [#842](https://github.com/abue-ammar/tinycast/pull/842) records that a CLI crash can leave a session under `~/.grok/sessions`, and that a weak sandbox is used when strict mode cannot start. Cleanup and fallback security modes must be visible in the design.
- Snippet expansion in [#98](https://github.com/abue-ammar/tinycast/pull/98) is disabled by default because it needs Input Monitoring and Accessibility. Sensitive capabilities should start off and require an explicit Settings action.

### Compatibility, imports, and distribution

- Raycast imports were a recurring compatibility boundary. [#112](https://github.com/abue-ammar/tinycast/pull/112#issuecomment-5140031851) found an out-of-bounds crash from a non-zero-index Data slice passed to decompression. [#306](https://github.com/abue-ammar/tinycast/pull/306) separates an oversized export from a wrong passphrase. Import errors need precise user messages and data-shape tests.
- The project had repeated Intel and older macOS work. [#117](https://github.com/abue-ammar/tinycast/pull/117) documents the cost of universal DMGs. [#213](https://github.com/abue-ammar/tinycast/pull/213) was an Intel proposal, while [#230](https://github.com/abue-ammar/tinycast/pull/230) added macOS 15 support. The supported matrix must be explicit, and each platform-specific path needs a real build check.
- [#815](https://github.com/abue-ammar/tinycast/pull/815) replaced CI with CodeRabbit and records the key risk plainly: reviews warn, but no test or build runs automatically. Review bots can find bugs, but they cannot replace executable gates.
- [#869](https://github.com/abue-ammar/tinycast/pull/869) found a 25 MiB Cloudflare asset limit when a 26.5 MiB video failed deployment. Distribution limits should be checked in a dry run before release.
- [#870](https://github.com/abue-ammar/tinycast/pull/870) found fork deploy failures and two live SEO routes with wrong indexing behavior. [#871](https://github.com/abue-ammar/tinycast/pull/871) then fixed 37 broken `llms.txt` links. Production route checks should resolve generated links, not only compile source files.

### Scope and process lessons

- A large feature can hide unrelated risk. The review of [#319](https://github.com/abue-ammar/tinycast/pull/319#pullrequestreview-5002954537) recommends splitting the 7,080-line, 84-file AI change before merge. The review of [#325](https://github.com/abue-ammar/tinycast/pull/325#pullrequestreview-5009414709) found unrelated runtime fixture changes mixed into OAuth work.
- [#232](https://github.com/abue-ammar/tinycast/pull/232#issuecomment-5303260025) reduced a Notes change after the initial plan grew past 10,000 lines. A narrow first version is easier to review and validate.
- [#840](https://github.com/abue-ammar/tinycast/pull/840) groups extension file-write guards, shell execution gating, and CI restoration. Security changes and build changes have different review evidence. Split them when possible.
- [#253](https://github.com/abue-ammar/tinycast/pull/253#discussion_r3798771795) found stale user aliases surviving deletion and a search ranking bug where a partial alias outranked an exact app name. Persistent indexes need deletion cleanup and ranking tests for both exact and weak matches.
- The refactor series [#156](https://github.com/abue-ammar/tinycast/pull/156) through [#202](https://github.com/abue-ammar/tinycast/pull/202) shows a useful pattern for a growing desktop app: define ownership and naming rules, use pure model code that a standalone harness can compile, and add completeness tests for persisted settings.
